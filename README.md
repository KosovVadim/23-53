# КРОК: FastAPI MVP

Бэкенд по UX из `23_53.zip` и выводам созвона. Фронтенд в архив не входит: исходные материалы содержали PNG, а не код интерфейса.

## Запуск

Python 3.12+. Команды выполняются из каталога проекта.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
set -a
. ./.env
set +a
uvicorn app.main:create_app --factory --host 127.0.0.1 --port 8000 --workers 1
```

Swagger: http://127.0.0.1:8000/docs. Нажмите Authorize и введите `local-editor-key` из примера конфигурации. Read-only ключ `local-viewer-key` видит только клиента `krasnodar`. Ключи из примера только для локальной демонстрации. Не коммитьте `.env` и замените ключи перед предоставлением доступа другим пользователям.

Альтернатива: после создания `.env` запустите `docker compose up --build`. Данные сохраняются в volume `krok-data`. Docker-конфигурация предоставлена, запуск контейнера не проверялся.

База по умолчанию `data/krok.db`. Начальные данные появляются только в пустой базе. Все люди, связи и взаимодействия вымышлены; названия клиентов взяты из UX. Числа в карточках вычисляются по данным, поэтому не повторяют нарисованные в макетах 12/34/33 контакта. У S7 намеренно пустая карта. `SEED_DEMO=false` отключает заполнение.

## Что работает

* Список клиентов: поиск, пагинация, число контактов, непросмотренные изменения и охват ЛПР.
* Карта: режимы клиента, сделки и человека; фильтры по подразделению, отношениям, статусу и имени. Ответ содержит `nodes`, `edges`, `center`, `ring_legend` и координаты для фронтенда.
* Контакты: создание, редактирование, предпочтения общения, интересы, потенциал и устойчивость с объяснениями. Оценки задаются явно человеком; прогноз ухода или психотип по косвенным признакам не вычисляется.
* Сделки: создание, редактирование, этап, сумма, участники и их роли.
* Связи: создание, основания, подтверждение/отклонение и уточнение описания.
* Взаимодействия: встречи, звонки, письма, мероприятия, заметки; фильтрация по человеку и сделке.
* Источники: сохранение текста, даты, ссылки; точные цитаты проверяются по исходному тексту.
* История: каждая успешная запись создаёт неизменяемый снимок клиента. Ползунок запрашивает карту по `version`.
* Фоновая обработка: задание сохраняется в SQLite, обработчик запускается вместе с API, после перезапуска незавершённые задания подхватываются снова. Ошибка не сохраняет частичный результат. Повторный запрос на обработку того же источника возвращает прежнее задание.
* Ассистент: отдельные диалоги для клиента, сделки или человека; сохранение сообщений, источники и номер использованной версии. При каждом сообщении контекст читается заново.
* Серверные права `editor` / `viewer` и доступ к конкретным клиентам. Проверяются также для истории, источников, заданий, чата и выдачи контекста.

## Привязка к UX

| Экран / действие | API |
| --- | --- |
| Карточки клиентов | `GET /api/v1/clients` |
| Открыть клиента по ссылке из CRM | `GET /api/v1/clients/{id}`; фронтенд использует id в маршруте |
| Карта клиента | `GET /api/v1/clients/{id}/map?scope=client` |
| Карта сделки | `GET /api/v1/clients/{id}/map?scope=deal&scope_id={deal_id}` |
| Карта человека и соседей | `GET /api/v1/clients/{id}/map?scope=person&scope_id={person_id}` |
| Карточка человека | `GET /api/v1/clients/{id}/people/{person_id}` |
| Ручная правка | `PATCH /api/v1/clients/{id}/people/{person_id}` |
| Ползунок истории | `GET /api/v1/clients/{id}/history`, затем `/map?version=N` |
| Основание связи | `GET /api/v1/clients/{id}/sources/{source_id}` |
| Подтвердить / отклонить | `PATCH /api/v1/clients/{id}/relations/{relation_id}/review` |
| Снять отметку об обновлениях | `POST /api/v1/clients/{id}/read?version=N` |
| Панель ассистента | `POST /api/v1/clients/{id}/chat` |
| Восстановить диалог | `GET /api/v1/clients/{id}/chat/sessions` и `/chat/sessions/{session_id}` |
| Загрузка протокола | `POST /api/v1/clients/{id}/sources` с текстом в JSON |
| Обработка протокола | `POST /api/v1/clients/{id}/sources/{source_id}/process`, затем `GET /api/v1/jobs/{job_id}` |
| Контекст для интеграций | `GET /api/v1/clients/{id}/context` |

Сворачивание панели, масштаб и положение камеры карты являются состоянием фронтенда. Кольца в MVP обозначают оценку отношений: strong=1, developing=2, weak=3, unknown=4. Это явное проектное допущение: макеты не описывают формулу. Координаты служат стартовой раскладкой, фронтенд может применять свою.

Охват = число ЛПР, с которыми есть хотя бы одно взаимодействие кроме заметки, делённое на число ЛПР. При отсутствии ЛПР `ratio=null`. Обновления = непросмотренные версии клиента, а не количество писем.

## Запись и ошибки

У клиента общий `version`. Для создания объектов передайте `expected_version` в query, для PATCH — в JSON. При конфликте сервер отвечает `409` и `current_version`: перечитайте данные, покажите пользователю конфликт, затем повторите осознанную правку. Изменения и снимок фиксируются одной транзакцией.

```json
{
  "expected_version": 1,
  "changes": {"title": "Руководитель информационной безопасности"}
}
```

Тела create/update описаны в Swagger. Служебные ID и версии нельзя менять через PATCH. Ссылки между объектами разных клиентов отклоняются. Цитаты должны точно входить в текст источника. Временные метки принимаются с часовым поясом. `401` — нет ключа, `403` — нет права записи, `404` — объект недоступен или отсутствует, `409` — конфликт, `422` — неверные данные, `502` — ошибка модели.

## Нейросеть и деморежим

По умолчанию внешних обращений нет. `mode=demo`: чат возвращает честно подписанный обзор текущего контекста, а не имитирует понимание произвольного вопроса. Для воспроизводимого показа извлечения используется точный шаблон:

> Николай Орлов и Ирина Кузнецова согласуют требования.

Имена должны совпадать с карточками. Обработчик создаст предполагаемую связь с точной цитатой. Другой текст может дать ноль связей — это нормальный результат демопарсера. Запустите `python scripts/demo.py` при работающем API для полного сценария (добавит тестовый источник и подтвердит найденную связь).

Для частной модели задайте `LLM_BASE_URL` (URL с `/v1`), `LLM_MODEL` и при необходимости `LLM_API_KEY`. Сервис должен поддерживать `POST /chat/completions`, а для извлечения — `response_format` с JSON Schema. Код адаптера в `app/ai.py`. Реальная модель не была доступна для проверки; HTTP-контракт проверяется тестом с подменённым транспортом. Ошибки модели возвращаются явно, без скрытого переключения на деморежим.

LLM создаёт только `proposed` связи. ID людей и цитаты валидируются; применение всей пачки атомарно. Свободный ответ чата не считается подтверждённым фактом. `citations` в ответе — источники переданного контекста, а не доказательство, что модель использовала каждый из них. В текущем MVP контекст выбранного клиента/сделки/человека передаётся целиком, плюс последние 20 взаимодействий. Векторный поиск и ограничения контекста для крупных клиентов — следующий этап.

## Границы MVP

SQLite и снимки JSON выбраны для быстрого запуска без внешней инфраструктуры. Запускайте **один Uvicorn worker**: восстановление фоновых заданий рассчитано на один процесс. Для масштабирования потребуются PostgreSQL, миграции схемы и отдельная очередь заданий. Ошибочное задание пока не перезапускается через API: исправьте источник, сохраните новую версию как новый источник и запустите обработку.

CRM, SSO, наследование реальных прав CRM, обратная запись, парсинг PDF/аудио, потоковый чат, отдельные ACL документов и production MCP-сервер в этот MVP не входят. Все источники внутри доступного клиентского пространства доступны его пользователям. Поэтому загружайте только общедоступные для этой группы тестовые данные. `/context` — обычный REST API, он не называется MCP. Для будущего MCP можно использовать те же проверки доступа и сервис контекста.

Метрики и предпочтения имеют ручной ввод и основания; автоматической оценки психологии, риска ухода или LLM-скоринга нет. Удаление сущностей намеренно не реализовано: ошибочную связь можно отклонить, сохранив историю. Аудит хранит пользователя, действие, время и снимок, но не является защищённым от администратора compliance-журналом.

## Проверка

```bash
pip install -r requirements-dev.txt
python -m pytest -q
```

Тесты покрывают изоляцию клиентов, роли, ссылки и цитаты, историю и конкурентные правки, сохранение после перезапуска, обновление контекста чата и атомарность обработки источников. `openapi.json` — экспорт схемы для фронтенда; живая версия всегда доступна на `/openapi.json`.

Использованные справочные материалы: [FastAPI lifespan](https://fastapi.tiangolo.com/advanced/events/), [тестирование lifespan](https://fastapi.tiangolo.com/advanced/testing-events/), [Pydantic serialization](https://docs.pydantic.dev/latest/concepts/serialization/).
